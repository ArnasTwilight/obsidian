Способы хранения lcode:
1. Если количество клиентов ограничивается порядком 2000 записей и будет происходить постепенно, то технический вариант с json можно оставить
   - Наименее трудозатратный вариант
   - Не самое удобное решение, если потребуется переиспользовать функционал в перспективе
   - Потребуется постоянная помощь разработчика в случае, если потребуется добавить или удалить lcode из списка
2. Создать интерфейс для загрузки файлов (csv) и сохранять в виде файла на сервере для дальнейшей работы:
   - Такой подход более трудозатратен
   - Мало чем будет отличаться от предыдущего варианта за исключеним того, что добавить новые lcode будет возможно без разработчиков
   - Могут возникнуть сложности с определением какие lcode были переведены, какие потребуется оставить, а какие нужно убрать в случае необходимости
3. Так же обратиться к созданию интерфейса, но уже не загружать файл, а напрямую записывать в БД и там же иметь список для переведённых lcode
   - Не имеет смысла, если функционал будет использован только один раз и более нам не потребуется
   - Потребуется сущность, назначение которой будет не до конца понятно
   - Наиболее гибкий вариант да изменений
   - Может полностью исключить вмешательство разработчика
