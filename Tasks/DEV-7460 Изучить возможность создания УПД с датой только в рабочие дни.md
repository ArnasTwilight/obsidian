Цель спайка - нужно понять, какую лучше всего сделать реализацию: 
1. Запрашивать данные со стороннего сервиса 
	**Минусы**:
	- Лишнее звено в цепи, если произойдёт падение, то работа остановится.
	- Придётся писать логику для получения данных со стороннего сервиса
	- Вероятные сложности при установлении связи между сервисами
	**Плюсы**:
	- Распределение нагрузки (В данном случае возможно будет на уровне погрешности, не значительно)
	- Меньше кода на стороне ББД
2. Хранить у нас в коде где-то 
	**Минусы**:
	- Хардкод, отсутствие гибкости
	- Усложнение поддержки продукта
	Плюсы:
	- Лёгкий доступ для разработчиков
3. Нужно ли УПД теперь начинать хранить в БД?
	**Минусы**:
	- Лишняя нагрузка на БД (возможно не значительная)
	- Предположительная сложность с определением полей
	**Плюсы**:
	- Гибкость
	- Нет необходимости в настройке, только создание новой таблицы
	- Лёгкий и стабильный доступ до данных

Для реализации изменения даты УПД может потребоваться расширение для определения праздничных и выходных дней, например [yasumi](https://github.com/azuyalabs/yasumi).

Либо воспользоваться сторонней API, например http://basicdata.ru/api/calend/

Для непосредственной реализации можно встроится в конец метода `get_upd_docs_list()` перед возращение результата и изменить дату УПД.
Таким образом дата УПД изменится при его формировании.

Наиболее предпочтительный вариант использовать [yasumi](https://github.com/azuyalabs/yasumi), чем другое стороннее API, как http://basicdata.ru/api/calend/.
